# Dyrane Weddings

A reusable wedding-experience product in which a formal share card opens into a cinematic, accessible spatial story.

**Production:** `https://weddings.dyrane.tech`

Alexander and Chioma are the yardstick build. It proves the complete public invitation grammar, publishing projection, personalized routing boundary, calendar and social artifacts, spatial presentation, semantic fallback, RSVP contract and event-collaboration seams. Couple and event content remains a reviewed yardstick dataset until a real wedding is published through the future Couple Studio workflow.

## Public experience

- `/` — Dyrane Weddings offer and package enquiry
- `/start` — progressive package enquiry
- `/the_ogranyas` — public yardstick invitation
- `/the_ogranyas/invite/{opaqueToken}` — personalized, non-indexable invitation
- `/the_ogranyas/calendar` — downloadable calendar artifact
- `/the_ogranyas/celebration` — public celebration and collaboration hub
- Dynamic root, public and personalized share cards are generated by editioned Next.js image routes.
- Wedding-scoped manifests, icons, logos, `robots.txt` and `sitemap.xml` are generated from the same published identity boundary.

The checked-in personalized token is a non-secret test fixture. Real invitation credentials must be random, hashed at rest, revocable and issued by the invitation service.

## Experience contract

The approved guest experience is governed by [`docs/EXPERIENCE-NORTH-STAR.md`](docs/EXPERIENCE-NORTH-STAR.md):

- pitch black, white and one exact celebration yellow;
- Space Grotesk hierarchy;
- a share card that transforms into one continuous spatial journey;
- immediate semantic content before WebGL is required;
- interruptible camera direction with manual scroll ownership;
- complete reduced-motion, no-WebGL and context-loss fallbacks;
- no ornamental wedding UI, hidden technical copy or false action states.

The public experience is a release candidate, not a claim that the full multi-tenant wedding platform is complete. The remaining Couple Studio, PostgreSQL publishing, guest delivery, notification outbox and reusable provisioning phases remain in [`docs/ROADMAP.md`](docs/ROADMAP.md).

## RSVP truth boundary

An RSVP is acknowledged only after durable event storage commits it.

- On the Sites deployment, the event-collaboration adapter uses D1 and private R2 bindings.
- On a host without that storage binding, the RSVP API returns `503` and the guest sees that the response was **not saved**.
- There is no simulated success response.
- Transactional couple notification and the broader PostgreSQL/outbox architecture remain roadmap work.

## Development

```bash
npm install
npm run dev
```

Core validation:

```bash
npm run verify
```

Full Chromium desktop and mobile release gate:

```bash
npx playwright install --with-deps chromium
npm run verify:release
```

Public production smoke:

```bash
npm run verify:production
```

Override the target when validating a preview or another canonical host:

```bash
WEDDINGS_PRODUCTION_ORIGIN=https://preview.example.com npm run verify:production
```

GitHub Actions runs the production smoke against `weddings.dyrane.tech` every day and on manual dispatch.

## Release rule

Do not call a response delivered, an invitation private, a media object deleted, a crawler artifact valid or a spatial fallback complete until the corresponding persisted or externally observed evidence exists.
